# Runner input freshness guard

The former conflict fallback reapplied the last-finishing run, even when its inputs were old. Publication now checks recorded input versions against the fetched branch before the first push and after every rejected push. It preserves unrelated branch commits and output folders.

`result_freshness.py` snapshots Git blob/mode identities for the job's non-output code, shared `jobs/_lib`, runner code, `needs.txt` roots, `triggers.txt` matches and `after.txt` predecessor outputs. Modified and untracked files are hashed from disk; absent sparse inputs fail rather than appearing consumed. The digest's dynamic summary/status/note reads are explicit. `run_jobs.sh` captures before execution, then retains `RUNNER_INPUTS.json` in the output and copies its original into the existing run artifact.

The publication projection includes exact outputs generated earlier in the same invocation, so a valid dependent chain can publish together. Independently advanced overlapping output is rejected before that projection can hide it. A stale member withholds the selected cohort. JSON diagnostics name changed paths, captured/branch object IDs, branch commit and rerun action; commit-time rejection is retained in the Actions summary and log because the existing artifact-upload step precedes publication. The guard does not replace current source/research/legal gates.

## Per-consumer output generation correction

Root review caught a same-run false rejection: a broad claim-kit-style reader could consume example-hello's unchanged base output, then example-hello would execute later and the blanket final-candidate projection would substitute bytes the consumer never read. Publication now keeps the whole-output concurrency rejection first, then projects each consumer's captured generation independently. Exact earlier-produced candidate bytes are accepted. Exact base bytes are accepted only while that producer's entire output on the branch remains unchanged from the captured base. New external source inputs and genuinely concurrent output advances still reject. The publication diagnostic records each consumer/producer generation choice (`same_run_candidate`, `captured_base`, or `unmatched`). No job order or compiler code changed.
