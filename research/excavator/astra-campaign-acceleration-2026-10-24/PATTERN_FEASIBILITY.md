* `batch.prepare` already freezes 1–50 dossiers, deduplicates identical source spans and mechanical tasks, groups exact actor/provision/exception patterns, and supplies shared `RATIONALES.json`. Each member retains earlier-end, scope, independent-command and savings checks. Partial claims already have a readiness route.
* `build.py` compiles undecided evidence into `OVERLAY_INPUTS`/`STATUS_LEADS`. `overlay-prepare` calls `freeze_evidence`, which builds and returns a complete **`base_dossier` before any status decision/review**. `batch.prepare` accepts explicit dossier paths and has no direct provisional-status check. Canonical dossier emission and working-claim promotion have later gates; those are not a prohibition on reading/preparing evidence.
* Thus removing an alleged universal “status before preparation” gate would duplicate an existing capability. A small wrapper could expose frozen undecided `base_dossier` records to the batch viewer, preserving null status and ownership. It would save navigation/repeated preparation, not authorize adjudication. No measured repeated agent cost establishes substantial benefit.
* X1 already generates template clusters, per-member differences and member-owned exact clause spans. The only additional integration identified is rendering these **different-source template/delta pairs** alongside existing batch text blocks, whose codec merges exact text hashes. That is an interface convenience, not a new legal inference engine. No evidence yet supports replacing full original inspection or independent member review with delta-only approval.
