You only PROPOSE; nothing is adopted. This step decides the status question and the reason for it; later steps (clause inventory, exact first-end dates, savings, counterevidence) are other workers' jobs, so do not build a full lifecycle here.
For each order: read its working text in full (best held text; OCR noise is common); read STATUS_LEADS, OWN_TERMS, CHAINS and the number_search hits in the evidence file; run `cruden.py number EO:N` if the export lacks hits; read every held text that cites the order and say whether any revokes, supersedes, modifies or restores it. Classify what the order does (e.g. public-land withdrawal or reservation, revocation of an earlier withdrawal, civil-service exemption for one person, appointment or classification rule, boundary change, regulation). Then decide: a one-time permission or appointment waiver used and spent can be "no" only if a source shows it was used (or the order itself shows it was self-executing on signature); a land reservation or withdrawal is "yes" only with a held source showing it still in force at 2026-10-14, and "no" only with a held instrument that revoked or released it; otherwise "undetermined" with the missing source (e.g. "BLM public land order revoking EO N / current land status record", "OPM/CSC record of appointment"). Up to 2 web lookups per order are allowed only to name the missing source precisely (do not treat a web page as held evidence).
Outcome per order: "done" when you make a source-backed yes or no proposal; "blocked:<acquisition>" when your proposal is undetermined for want of a source; "failed:<reason>" for tool failure.
