**Risks found in review.** Earlier copied main batch.py included an extra terminal newline (44,358 bytes, Git blob 820bf90…). A rerun correctly refused once the cache represented the real source. Separate GitHub UTF-8 and base64 reads confirm the real main file is 44,357 bytes, Git blob 92d09ce698f598bda75c5c73ff7eb18b4607b5f0. The PR133 historical packet was also checked directly against remote blob 7ab22ae86a793173e3bdaf74a58243e887996e3e. Supersede the earlier pins and keep the failed attempt visible.

Initial grouped predicates incorrectly reused an integer-span hit for a boolean offset, allowed an empty quotation/zero-width span, and raised on changed non-UTF-8 bytes before detecting a hash mismatch. These are engineering prototype defects, not native verifier defects. Grouping itself presupposes one immutable byte snapshot: if a file changes between references, fresh per-reference reads detect the change and a one-read group cannot. Never treat this as equivalent for mutable paths or across independent/blinded review contexts.

The proposed paired test should use fresh, unexposed arms, the same exact evidence obligations and control standards, and a competent baseline allowed to invoke maintained tools. Count model, coordinator, preparation, reviewer, correction and fallback work; report cache/fresh/output separately and missing usage as unknown. Count setup once and never translate machine milliseconds or transport bytes into model tokens. A single matched packet can support a routing decision but cannot establish a population effect.

**Final source-probe result.** The repaired prototype passes all three discovered cases and checks the real 14 dispositions identically. An independent counter wrapped the actual span evaluator: 14 reads/14 evaluations for occurrence-wise processing; 4/4 for the competent per-claim baseline; 1/2 for an immutable pooled snapshot. The receipt hash is identical in all three arms. The separate mid-invocation mutation probe deliberately remains non-equivalent; it documents the boundary, not a repair target for a cache to deploy.
