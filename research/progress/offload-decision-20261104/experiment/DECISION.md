# Reject a new source-reference dictionary codec

The maintained `batch.encode`/`decode` already shares exact source dictionaries,
repeated objects and strings. A new equivalent codec would duplicate engineering.
Retain the existing representation machinery; do not infer that changing the
model-facing format or packing more orders into one context saves research work.

This replay uses the exact genuine canonical Erasmus c1 claim file published at
main `600ae3018f71025b3e53dc8538b8f92e6e159b76`, not a control packet. All 15
versions are historical inputs. It neither contacts workers nor reads current
assignments, producer outputs, usage, caches, control keys or planted cards.
`SOURCE_PINS.json` records exact Git blobs, SHA256s and bytes. Raw inputs remain
ignored. The 15 claim identities are in the compact result, with no control
membership or outcome labels.

The first replay consumed a batch.py copy with one extra trailing newline and
incorrectly described that copy's computed blob as native. The reviewer then
observed the expected stale-pin refusal after the shared copy was corrected.
`SOURCE_PIN_CORRECTION.json` preserves that superseded pin, bounded result and
refusal. The final replay uses an independent local copy of the externally
confirmed main blob `92d09ce698f598bda75c5c73ff7eb18b4607b5f0` (44,357 bytes),
with unchanged output sizes and reconstruction hashes; only corrected-run
machine timings govern `RESULTS.json`. The reviewer also externally confirmed
the other two input blob identities.

The competent baseline serializes the same complete values as compact canonical
JSON, with no whitespace inflation. The existing codec requires dossier
fingerprints, so each opaque canonical claim receives an integrity shell;
both arms include the identical shell. This is a representation harness, not a
new dossier or an ordinary `kit view` execution. The harness executes unchanged
AST-extracted `canonical_sha`, `canon`, `digest`, `safe`, `encode` and `decode`
from exact pinned source, avoiding missing sparse import dependencies.

The literal unwrapped canonical claim map is 352,977 bytes. Wrapper overhead is
2,568 bytes in both comparable arms. Existing codec framing, source dictionaries
and shared-object tables are all included in the 162,556 bytes. Every reconstructed
canonical byte is equal to baseline (SHA256
`4c53c17cde7180ab78e96c2034046d4bca6e0bf1739325ce2711d0b162a3153e`).

The 71 repeated complete source-dictionary occurrences split into 30 within an
order and 41 additional repeats across orders. Each actual claim has seven source
dictionary occurrences and five distinct dictionaries. The ordinary worker
instructions use one order per slim view: the pooled count is therefore a
conditional shared-context opportunity, not a count of tasks removable from
current production. `RESULTS.json` separately retains every cold one-order
baseline/codec size and single bounded machine timing; it does not assume that
the other fourteen orders are needed for a single lookup.

Current `geddes._canonical_claim_view` labels filed claims as prior drafts, may
cap strings by default, and offers full-claim access; ordinary `geddes.view`
includes an evidence source catalogue and other context. Those are different
output contracts. This replay measures the full prior-claim payload only. It
does not claim its literal arm is the complete current slim view or that a
dictionary preserves the placement and accessibility of an actual model prompt.
If decoded before prompting, the model receives the original bytes and there is
no prompt reduction. If left encoded, dictionary instructions, lookup effort,
selective expansion/fallback and source access need prospective measurement.

The potential offload is exact equality identification and transport of repeated
values. The existing codec performs that already. This experiment demonstrates
zero source reads removed from independent examination, zero substantive review
decisions removed, and zero observed model tool calls removed. It establishes
no token, cache, cash or active-labor saving. Source signatures, all exact spans,
qualifications and per-order application reasoning remain intact and require
their ordinary independent examination. Sharing a prior claim does not approve
it or substitute for a held raw source.

Stale raw-input pins, duplicate JSON keys, changed member versions, changed or
missing dictionaries, cyclic references and reserved codec markers all refuse;
source-field reconstruction is exact. These eight bounded checks are retained
in `RESULTS.json`. A changed source, claim, codec or schema invalidates this
replay; fetch/pin again and rerun. Reusing exact-equality groups across changed
input versions is outside the demonstrated contract.

For a future consumer, break-even requires its observed avoided model work to
exceed encoding, decoding, instructions, lookup/fallback, independent checking,
coordination and maintenance costs. In bytes, a pooled literal transport has
192,989 bytes of headroom before added instructions/fallback; this is neither a
token estimate nor a monetary threshold. With expanded model input the byte
headroom is zero. A new codec has no demonstrated incremental benefit over the
maintained codec, so its expected positive setup/maintenance cost has no observed
break-even under the tested output contract.
