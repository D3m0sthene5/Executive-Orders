# GitHub Actions runtime, November 4

Base: a3bfac64b3e1c43400a8ed8c744419eb17f6e2e6. Measure Git job execution, publication, and queue delay separately.

Production run [41886953010](https://github.com/D3m0sthene5/Executive-Orders/actions/runs/41886953010) took 52 minutes. Input materialization selected 9.51 GB across 103,915 paths. Its 11 subjobs ran sequentially. Claim-checker occupied 18m14s, claim-kit 13m22s. This patch compacts redundant positive sparse rules. The set of declared inputs, their fingerprints, and the post-checkout existence checks are preserved.

**Matched native Git comparison.** On the pinned tree, 30 selector declarations for ten of the eleven production jobs were reproduced. Valla was excluded from this benchmark because its dynamic input closure requires separate proof. Of 106,790 tracked paths, the baseline and new Git matcher selected an identical ordered sequence of 103,988 paths (SHA-256 a8d3becde0957368befc3d9da5c847ade5adf0ec022beb68ac1cafd4a91f9a32). Positive rules fell from 99,785 to 5. One local matcher pass took 96.9813s and 0.14044s respectively. Reproduce with compare_sparse_rules.py from the repository root with all ten jobs' declarations checked out. A separate local fixture using checkout and three subsequent Git sparse additions averaged 10.23s before and 3.51s after over two runs per arm. End-to-end hosted savings depend on the selection and runner.

**PR checks.** On [PR 139's Valla run](https://github.com/D3m0sthene5/Executive-Orders/actions/runs/41894717955), the standalone Mountweazel scan took 174 seconds and checked the same full checkout as a test in the unit suite. The consolidated test executes the native CLI and asserts minimum scan coverage. The full checkout is still needed for leak detection. A newer run on the same PR can now cancel the superseded read-only run.

**Manual diagnostic.** In Run jobs, select diagnostic to run only the named jobs. It keeps attempt and checkout receipts in an artifact, uses a restore-only cache, and disables publication. The selected jobs still execute normally and may contact external sources. Using all 69 runnable folders and 36 after.txt declarations from the pinned tree, a claim-checker request selects 18 jobs normally and 1 in diagnostic mode; readiness-tracker selects 15 versus 1. The default mode still publishes with consumers. The summary reports direct versus downstream selection, execution time, failures, and actual publication outcome.

**Freshness.** The broad input fallback can bind the runner's own temporary cache, failed-attempt and receipt files. The exemption requires an audited, unchanged Valla reader, validated linked inputs, and no explicit declaration that selects the file. Tracked data, declared inputs, reviewed pointers, and unknown reader versions remain guarded. Both capture and publication verify the reader pin. Changing the reader still requires a separate audit. No run timings or savings have been imputed for avoided failures.

**Review.** Separate engineering workers implemented and reviewed these changes. Campaign token and active-labor totals are unavailable. Scientific approvals, cases, and readiness counts are outside this patch.
