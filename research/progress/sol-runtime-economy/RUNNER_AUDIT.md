# Runner fallback capture audit

Baseline: `2c85459cf38b08dc1eea6d7c84a74268fa45c28e`. Scope: read-only code and workflow inspection; this report is the only requested write. Configured worker model: `gpt-6.1-terra`, high reasoning. Token and cash usage were not exposed; elapsed time was not reliably measured.

## Finding

The integrated certificate report records run 41822603367 rejecting seven results, with Valla on `audited_version_changed` fallback after a Valla implementation change. Claim-checker had produced 175 untracked `.job-cache/claim-checker/text/*.json` files. These appeared in Valla's captured inputs but not the branch tree, producing `inputs_changed`. This is historical evidence from `research/progress/integration-20261104/VALLA_CERTIFICATE.md`; this audit did not reproduce the hosted run.

The code explains that result. `result_freshness.scope()` appends `*` when Valla's dynamic read closure is incomplete or its implementation is uncertified; `fnmatch` lets `*` span directories. `run_jobs.py` makes `.job-cache/runner-attempt` before capture and gives jobs `.job-cache/<job>`; the workflow also restores `.job-cache` before jobs run. `working()` inventories modified and untracked files via `git ls-files --exclude-standard`, then hashes matching live files. The baseline root `.gitignore` does not ignore `.job-cache`. `check()` compares captured inputs to the branch tree, substituting selected producer output generations, not cache contents. Thus a nonempty untracked earlier-job cache is captured under the fallback and cannot match the branch. `test_valla_materialization.py` creates a fixture `.gitignore` containing `.job-cache/`, masking this real policy difference.

## Narrow change assessment

No implementation patch is recommended on the evidence inspected. Excluding the cache from the fallback in `.github/scripts/result_freshness.py` would alter the conservative read contract precisely when the implementation is unaudited. The existing exact `referenced_files` mechanism force-hashes known ignored or untracked references, but it cannot establish that an unknown implementation makes no implicit cache read. A safe fix needs a demonstrated contract that cache contents cannot affect published output, or a scoped design that preserves detection of any cache bytes actually consumed. Avoid a blanket exclusion without that evidence. General `.gitignore` changes are outside this assignment.

A future reviewed change should test a real two-job sequence in which a prior job writes cache and uncertified Valla captures inputs; verify unrelated untracked inputs remain visible and reject against the branch; verify explicitly referenced cache inputs remain versioned and rejected when uncommitted or mutated; verify selected producer generations still work; and retain incomplete-closure rejection. Model the actual root ignore policy rather than adding fixture-only cache ignores. Confirm exact behavior with tracked cache paths and with newly introduced reads. Changes to runner, freshness, materializer, workflow, `jobs/_lib`, or Valla are within Valla's implementation signature and invalidate its certificate until the resulting exact read closure is separately audited and the signature updated. The fallback is not a substitute for certificate review.

## Workflow and publication implications

`run-jobs.yml` triggers on **any branch push** touching `jobs/**`, `.github/scripts/**`, or its own workflow file. `pick_jobs.py` selects `example-hello` for script or runner-workflow changes if runnable; the workflow can run it and commit results to that same branch. A draft PR does not suppress this push event. The scheduled three-hour and daily runs are separate triggers; report-only changes are not a guarantee against later scheduled selection. `road-tests.yml` runs on PRs touching `.github/**` or `jobs/**` and on matching main pushes; `kean.yml` runs for every PR and main push. Its registration gate should be considered by the coordinator.

For this audit alone, keep the branch diff limited to this report and other explicitly authorized non-triggering paths, inspect the exact path list before pushing, and open a draft PR only if authorized. That avoids the listed push-triggered Run jobs path filters, though the PR still runs Kean. A future `.github/scripts` patch cannot be pushed under these workflow rules while guaranteeing no automatically generated smoke job: prepare and review it locally first, and coordinate an explicit decision about the automatic run or an independently authorized workflow-control mechanism before pushing. Do not dispatch Actions as part of this audit.
