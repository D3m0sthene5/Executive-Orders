# 3. X1 reads retained event sources and exposes source pointers

The existing event reader now consumes source-ladder and Astra retention independently. Each representation carries provider-relative text/raw paths, raw hash, exact source-record line/hash, text hash, selected pages, and a separate raw-custody result. Retention's declared text hash must match; legacy Panizzi text without a declared text hash is labeled as a computed legacy-text pin. Existing raw files are checked within the documented size bound; unavailable raw bytes are never described as rehashed.

All alternative excerpts survive. A passing Panizzi representation cannot be overwritten by a narrower retention excerpt of the same raw document. Different raw hashes for the same requested URL remain a conflicting-version hold. Missing text, unsafe paths, mismatched hashes and absent phrases remain explicit. Event specifications, phrase requirements, roles and individual legal-review obligations are unchanged.

EVENT_CANDIDATES.csv now carries JSON source records. Existing batch sheets expose event state, role and exact representation pointers in event_source_details; they no longer discard this handoff. No automatic event-to-original attribution is added. FLPMA's not-an-ending role and blank agent/reviewer judgment fields are preserved.

Added the existing retention job to X1's same-run predecessors. No claim-kit-to-Shepard edge is added. Eleven focused local tests pass, including a sheet-level integration test, both providers, alternate excerpts, text/raw mismatches, missing text, conflict, traversal and explicit absence of byte verification. The original sheets.py was reconstructed and matched its exact main Git blob before the patch. Full corpus regeneration remains a separate branch validation, not a claimed count gain.
